# xhs-mcp

让你的 AI 助手直接读写你的小红书账号：看自己的笔记数据、把内容填进发布页。

它是一个本地 MCP server，通过驱动**一个真实的浏览器窗口**来操作，全程不需要你的账号密码。

> **和官方无关。** 本项目与小红书官方没有任何关联，未获授权或认可。自动化操作可能触发平台风控，存在限流或封号风险，请自行判断是否使用，详见 [免责声明](#免责声明)。

## 它能做什么

| 你说 | 它做的 |
|---|---|
| 「检查一下登录还有效吗」 | 分别探活创作者中心与 www 域 |
| 「列一下我最近 5 篇笔记」 | 读笔记列表，带点赞/阅读数据和可访问链接 |
| 「看看这篇的正文」+ 链接 | 读正文、话题标签、图片地址 |
| 「这篇曝光多少、涨了几个粉」 | 曝光/观看/点赞/收藏/评论/分享/涨粉/人均时长/封面点击率 |
| 「我最近哪篇笔记表现最好」 | 时间窗内按曝光排行 + 整体汇总 |
| 「把这段内容存成草稿」 | 填好标题正文图片话题，**停在页面上不提交** |
| 「直接发布」 | 点「发布笔记」，需显式确认 |

一共 9 个工具，覆盖读取、数据分析、内容发布三类。

## 为什么不用官方 API

小红书开放平台的笔记发布接口要求企业主体（营业执照），个人号拿不到权限；而且 access_token 只有 2 小时，没有 refresh token。

所以这里走的是浏览器自动化：**用你自己的登录态，操作你自己的账号**。

有两个设计因此变得重要：

- **不保存账号密码。** 网页版密码登录本身会触发滑块/短信验证，而且密码落盘是这个方案里最不该有的风险。改用扫码一次，之后复用浏览器会话。
- **不伪造请求签名。** 小红书的接口有 x-s/x-t 签名，逆向维护成本高且随时失效。这里的做法是让页面自己发请求，我们只旁观响应。

## 安装

需要 **Node.js 20+**。

```bash
# 1. 装包
npm install -g xhs-mcp

# 2. 下载浏览器内核（约 150MB，只需一次）
npx playwright install chromium
```

### 接入你的 AI 客户端

MCP 客户端只认一个命令，配置 `npx` 即可：

**Claude Desktop** — `~/Library/Application Support/Claude/claude_desktop_config.json`（macOS）或 `%APPDATA%\Claude\claude_desktop_config.json`（Windows）：

```json
{
  "mcpServers": {
    "xiaohongshu": {
      "command": "npx",
      "args": ["-y", "xhs-mcp"]
    }
  }
}
```

**Cursor** — `~/.cursor/mcp.json`，格式同上。

**其他客户端**（Cline、Continue、WorkBuddy 等）同样是「命令 + 参数」的形式，填 `npx -y xhs-mcp` 即可。

## 第一次使用：扫码登录

配置好后，在对话里说「登录小红书」，它会在你屏幕上弹出一个浏览器窗口。

**用手机小红书 App 扫码**，登录态会保存到本机，之后不用重复。

看到类似输出就是成功了：

```
{"loggedIn": true, "nickname": "你的昵称", "redId": "你的小红书号"}
```

### 窗口停在登录页是正常的

小红书有**两套独立会话**：创作者中心（读列表、发布、看数据用）和 www 域（打开笔记详情用）。

两者可能一个有效一个失效。如果工具说 `creatorLoggedIn: true` 但 `wwwLoggedIn: false`，意思是：**功能全部正常，只是浏览器打开 xiaohongshu.com 会显示登录页**。

想消除这个登录页，重新扫一次码即可。

## 工具清单

### 读取

| 工具 | 说明 |
|---|---|
| `xhs_auth_status` | 分别探活两个域，返回 `creatorLoggedIn` / `wwwLoggedIn` |
| `xhs_list_my_notes` | 笔记列表（`limit` 默认 20） |
| `xhs_get_note` | 单篇正文/话题/图片/互动数（`target` 传 URL 或 ID） |

### 数据分析

| 工具 | 说明 |
|---|---|
| `xhs_get_note_stats` | 单篇指标 + 时间窗汇总 + 曝光排名 |
| `xhs_list_note_stats` | 时间窗内按曝光排行（`days` 默认 30） |

指标口径：`impressions` 曝光、`reads` 观看、`collects` 收藏、`fansGained` 涨粉、`avgViewSeconds` 人均观看时长、`coverClickRateText` 封面点击率。

**为什么要一起返回汇总和排名**：单看「曝光 347」没有意义，配合同期 3 篇共 755 曝光、这篇排第 1，才读得出好坏。

### 写入

| 工具 | 说明 | 风险 |
|---|---|---|
| `xhs_save_draft` | 填好内容停在页面上，**不提交** | 低 |
| `xhs_publish_note` | 真正点发布，需 `confirm=true` | 高 |

### 管理

| 工具 | 说明 |
|---|---|
| `xhs_login` | 扫码登录 |
| `xhs_close_browser` | 关闭浏览器、释放 profile 锁 |

## 内置的安全边界

这些限制**写死在源码里，不提供开关**。原因很简单：一旦能关，迟早有人在「我就试一下」的时候关掉，然后账号被限流。

| 限制 | 值 | 说明 |
|---|---|---|
| 发布间隔 | 10 分钟 | 两次真实发布之间低于此值直接拒绝 |
| 写入节流 | 8 秒 | 连续打开发布页/上传时强制等待，接近真人节奏 |
| 输入方式 | 逐字符 | 带随机延迟，避免整段文本注入被识别 |
| 浏览器模式 | 有头 | headless 极易被判定为机器人 |

另外：

- **不保存账号密码**，只保留浏览器会话
- 只操作你自己的账号，不含点赞/评论/关注/搜索他人内容
- 失败自动截图存到 `~/.xhs-mcp/errors/`

## 已知限制

| 限制 | 说明 |
|---|---|
| **必须有桌面环境** | 需要弹出真实浏览器窗口。纯服务器/容器环境用不了 |
| **Windows / macOS / Linux** | 三平台都支持，但只在 Windows 上做过完整验证 |
| **数据中心只覆盖近期笔记** | 无论查询时间窗多大，接口最多返回近期发布的作品 |
| **数据中心单页 10 条** | 窗口内超过 10 篇会被截断，返回里 `truncated: true` |
| **发布行为未在真实账号验证** | 避免产生公开内容，测试时只验证到「填好但不提交」 |
| **不支持视频笔记** | 只做图文 |
| **不支持搜索他人内容** | 有意不做，降低风控风险 |

### 数据目录

登录态默认存在 `~/.xhs-mcp/`。可以用环境变量改位置：

```json
{
  "mcpServers": {
    "xiaohongshu": {
      "command": "npx",
      "args": ["-y", "xhs-mcp"],
      "env": { "XHS_MCP_HOME": "/path/to/your/dir" }
    }
  }
}
```

**这个目录等同于账号凭据。** 不要提交到版本库，不要分享，不要放进云同步目录。

## 常见问题

**报 `Target page, context or browser has been closed`**
浏览器 profile 被别的进程占用了。同一时刻只能有一个实例使用 `~/.xhs-mcp/profile`。关掉弹出的浏览器窗口，或用 `XHS_MCP_HOME` 换个目录。

**报「找不到 Chromium」**
运行 `npx playwright install chromium`。

**发布的笔记图片不对**
封面裁切需要人工确认，工具不处理封面选择。

**改版后某个工具失效了**
小红书前端会改版。这一步没法避免，但修复通常很小：改 `src/config.ts` 里的接口特征，或 `src/tools/publish.ts` 里的选择器。欢迎提 issue 附上报错信息。

## 从源码开发

```bash
git clone https://github.com/zw-wang820/xhs-mcp.git
cd xhs-mcp
npm install
npx playwright install chromium
npm run build

npm run login                                       # 扫码登录
npm run call -- xhs_auth_status                     # 命令行调任意工具
npm run call -- xhs_list_note_stats '{"days":7}'    # 传参
npm run call -- --list                              # 列出全部工具与参数
npm run smoke                                       # 协议握手 + 工具注册检查
```

`npm run call` 不经过 MCP 客户端，直接对单个工具发一次调用，排查问题时比在对话框里试快得多。
